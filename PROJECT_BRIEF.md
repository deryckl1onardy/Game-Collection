# Shelf — physical-feeling digital game collection

A personal site that presents a digital game library as physical objects: box,
cover art, disc, and manual. Not a storefront, not a launcher — a shelf.

> **Note:** this is the original brief as written. Several decisions here have
> since been revised through grilling — see `docs/adr/` for the current state,
> especially ADR-0003 (single-user), ADR-0005 (wrap tearing), and ADR-0006
> (manual game playtime). Where this document and an ADR disagree, the ADR wins.

## Why this exists (what it does better than Steam/PSN)

Two goals, in priority order:

1. **Backlog psychology.** Platform libraries make a backlog feel like guilt — a
   flat wall of unplayed titles. Physical framing reframes it: unplayed becomes
   *unopened* (anticipation, not shame), and abandoned games get resurfaced as
   "you were 2 hours into this" rather than "you never finished this."
2. **Unify what's fragmented.** Steam, PSN, Epic, GOG, Switch, physical discs —
   nobody has one shelf. This is one place that is *yours*, with zero commerce,
   no sale banners, no upsells.

Explicit non-goals: launching games, storefront features, social feeds.

## Decisions already made

**Browsing model.** Grid-first, not literal shelf-spine browsing (painful at
100+ games). Filterable by genre/tag, platform, and play status, plus search.
Clicking a cover zooms into the tactile single-case view.

**Case view.** Interactive 3D — orbit/pan/zoom (drag, scroll, or arrow keys +
/− to nudge, "r" to reset the framing), open to reveal disc + manual.
Photo-real direction (glossy plastic, real shadows), not illustrated/flat.
Camera easing and the hinge/wrap animation both collapse to instant when the
OS asks for reduced motion.

**Homepage.** Two low-pressure surfaces above the grid:
- *Continue where you left off* — 1–3 unfinished games, spotlight not list
- *Pulled from the shelf today* — one random near-zero-playtime game

Both refresh per visit/day so opening the site is a small ritual.

**Backlog definitions.**
- `unopened` — zero playtime. Rendered with shrink wrap still on.
- `unfinished` — has playtime, low completion, no `finished` flag.
- `finished` — user-set flag.

Achievement % is a *signal*, never the source of truth: it nudges a game into
"probably finished, confirm?" but the manual toggle always wins. Many games gate
100% behind multiplayer/collectible grinding, and plenty ship with no
achievements at all.

**Tearing the wrap.** First open of an `unopened` game removes the shrink wrap
permanently. The state change is the point — it's the backlog mechanic made
physical.

> Superseded by ADR-0005: the wrap comes off when *playtime* rises above zero,
> not by a gesture in the app.

**Library card.** The manual carries a stamped date card showing session history
("a burst of stamps in 2022, nothing since, one last month"). Diegetic
alternative to a playtime chart. Generated by diffing playtime between syncs —
so start recording sync deltas from day one.

**Asset tiers** (sourcing is best-effort, quality will vary):
- T1: box + disc + manual — hand-curated for favorites
- T2: box + disc, no manual
- T3: cover only, simpler case

The 3D case must be modular so manual/disc are optional inserts, not fixed
structure. A T3 case should look intentional, not broken.

## Architecture

Next.js (App Router) + React Three Fiber + drei, deployed on Vercel.

R3F over raw Three.js because UI state and 3D state are tightly coupled here
(open/closed, current game, wrap torn). drei supplies `Environment`,
`ContactShadows`, `PresentationControls` (damped drag-to-rotate), `useTexture`.

### Two rendering modes — do not render 100 cases

- `/library` — 2D grid of cover images only. `next/image`, lazy loaded,
  virtualized past a few hundred. No WebGL. Stays fast.
- `/game/[id]` — mounts Canvas, one case, full quality.

Transition: animate the 2D cover to the position/scale the 3D case will occupy,
then crossfade to the canvas once textures resolve. The cover appears to *become*
the object.

### Data pipeline

```
Vercel Cron (nightly)
  -> /api/sync   (server-side, API key never leaves the server)
       Steam IPlayerService/GetOwnedGames
         -> appid, name, playtime_forever, playtime_2weeks, rtime_last_played
       Steam ISteamUserStats/GetPlayerAchievements
         -> completion % (only for games with stats)
       download cover once -> blob storage
       upsert -> DB, and write a session row if playtime increased
```

`rtime_last_played` powers "untouched for N months".
`playtime_2weeks` powers the "warm / momentum" signal for resurfacing.

**Covers must be served from your own origin.** This is not optional — see CORS
note below.

### Platform support reality

| Platform | Access |
|---|---|
| Steam | Official API. Easy. Requires public profile. |
| Epic | No official API. Unofficial libs, fragile. |
| GOG | Unofficial API only. |
| PSN | No public API. Unofficial endpoints, shakiest of all. |
| Switch | No access. Manual entry only. |
| Physical | Manual entry. |

So: Steam auto-syncs, everything else is manually entered but **styled
identically**. Unification happens at the presentation layer. There should be no
visual tell about which platform was easy to pull.

### Schema sketch

- `games` — id, source, source_id, title, cover_path, playtime, last_played,
  achievement_pct, genres[]
- `user_game` — status, finished_at, note, wrapped
- `sessions` — game_id, seen_at, playtime_delta   ← this *is* the library card

> `wrapped` removed per ADR-0005 — wrap state is derived from playtime.

## Technical gotchas already hit (do not rediscover these)

**1. Beveled geometry is deeper than its nominal thickness.**
`ExtrudeGeometry` with `bevelThickness: B` and `depth: D` spans `D + 2B`, not
`D`. Art planes placed at `D/2 + epsilon` end up buried *inside* the shell and
render invisibly. Always offset art by `SHELL/2 + BEV + margin`. This cost a
full debugging round — everything rendered as blank gray plastic.

**2. CORS blocks WebGL textures from Steam's CDN.**
WebGL refuses to upload a texture it isn't permitted to read. Loading Steam
covers cross-origin fails outright from `file://` (null origin), and is fragile
in general. Serving covers from your own origin removes the problem entirely —
which is why the import step downloads covers rather than hotlinking. During
local prototyping, `python3 -m http.server` is enough to unblock.

**3. Physical materials in Three r128 need PMREM environment maps.**
Assigning a raw `CubeTexture` to `envMap` / `scene.environment` gives unreliable
clearcoat. Run it through `PMREMGenerator.fromCubemap()`.

**4. Floor picks up the environment map** and glows washed-out gray. Set a low
`envMapIntensity` on the floor material.

**5. Set texture anisotropy** or angled spine text shimmers badly.

**6. drei's `<Environment preset="…">` loses the WebGL context.**
Reproducible on a clean load: the context dies before the HDR is even
requested, and the case renders as nothing at all. Bisected against a minimal
R3F scene, which survives — the preset is the trigger. It is also the wrong
shape for this project regardless: presets fetch an HDR from an external CDN at
runtime, which is the same external-origin dependency gotcha 2 rejects for
covers. Use `StudioEnvironment` (`src/components/case/StudioEnvironment.tsx`)
instead — canvas cube faces run through `PMREMGenerator.fromCubemap()`, exactly
as the v4 prototype did. Self-contained, and it satisfies gotcha 3.

**7. Screenshots of the first frame lie.** The canvas reports the right size and
an unlost context while still painting blank; the case appears a beat later.
When verifying visually, settle the page before believing an empty frame.

**8. PGlite must be in `serverExternalPackages`.**
It loads Postgres as WebAssembly from its own package directory; bundling it
breaks that lookup and the first statement fails with an opaque
`Failed query: CREATE SCHEMA ...`. Already set in `next.config.ts`.

**9. Pass migrations an absolute path.**
`migrationsFolder: "./drizzle"` resolves against the server runtime's cwd,
which is not reliably the project root. When it misses, the migrator finds no
files, *succeeds silently*, and the next query fails with `relation "games"
does not exist` — which looks like a schema bug rather than a path bug. Use
`path.join(process.cwd(), "drizzle")`.

**10. One process at a time may hold the PGlite data directory.**
Querying `.pglite/` from a script while the dev server is running reports an
empty database. Stop the server before inspecting it.

## Case geometry constants (validated in prototype)

```
W     = 1.86   // panel width
H     = 2.62   // panel height
THICK = 0.26   // closed case thickness (= spine width)
SHELL = 0.05   // panel thickness
BEV   = 0.008  // bevel, adds to depth on BOTH faces
HALF  = SHELL/2 + BEV        // true half-depth of a shell panel
```

Layout: back shell at `z = -THICK/2 + SHELL/2`; spine at
`x = -W/2 - SHELL/2`, full `THICK` depth; hinge group at
`(-W/2, 0, THICK/2 - SHELL/2)` with the front shell at local `x = W/2`.
Cover art plane at local `z = HALF + 0.005`. Disc is a `RingGeometry(0.1, 0.7)`
— gives a real center hole with usable UVs.

Steam portrait cover art (`library_600x900_2x.jpg`) is already box-cover
proportioned, so it maps to the front panel with no cropping.

## Build order

1. Port the case to R3F, single hardcoded game. De-risks the hardest part.
2. Library grid + filters against seeded/manual data.
3. Steam sync route + cover download + DB.
4. Homepage spotlight surfaces.
5. Asset-hunt T1 games; graceful fallback for the rest.
